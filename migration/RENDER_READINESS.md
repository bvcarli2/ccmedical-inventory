# Render deployment readiness — intentionally not deployable

The Render production deployment remains blocked by the explicit `RENDER` guard in `app.py`. Do not disable it or deploy the staging bridge.

## Intended configuration (after independent security approval)

- Python 3.12 web service, Gunicorn, no Flask development server
- Managed PostgreSQL 18 with encrypted connection, restricted network access, backups, and tested restore
- Environment secrets: strong `CCM_SECRET` generated by a secret manager; production PostgreSQL connection string; no credentials committed to Git
- `SESSION_COOKIE_SECURE=True`, HTTPS only, trusted proxy configuration, restrictive host validation
- Dedicated production database migrations, with schema version tracking and rollback procedures
- Health endpoint, structured request logging, error monitoring, database pool limits, request timeouts
- Separate development, staging and production environments; no live customer data in CI
- Employee provisioning via operator-only CLI commands, unique initial passwords, secure credential delivery, offboarding and password-reset policy

## Remaining production blockers

1. The PostgreSQL staging dispatcher intentionally exposes only selected endpoints; receiving, core detail, and several product operations still need complete end-to-end UI validation.
2. Existing product-admin temporary password/session mechanism must be removed or fully replaced for production.
3. Login throttling needs concurrency/race-condition tests and IP-based protection.
4. Every write endpoint requires explicit permission, CSRF, transaction, and audit testing. Review all read endpoints for sensitive-data authorization.
5. Test inventory and repair workflows with realistic synthetic records and verify financial totals.
6. Add secure file upload limits, scanning and storage controls before accepting customer photos and documents.
7. Independent security review and authorized owner sign-off are required before changing the startup guard.

**Do not add a deployable Render Blueprint or web service until these blockers are cleared.** The isolated Render database is not changed by these commits.
